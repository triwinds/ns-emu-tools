## 1. 目标与实施边界

在已能运行一次 Neural Rendering（NR）的接入层上，增加两类可复用能力：

1. 多次 NR 推理：多个独立实例串联，每个实例分别维护时序历史和参数。
2. Look 调整：控制模型带来的明暗、颜色、色相、整体光照与细节变化，随后增加光晕抑制和可选的时间平滑。

算法与游戏识别解耦。不同游戏主要保存参数预设，不为每个游戏重写推理调度和 Look shader。

本计划不包含重新训练或修改 NVIDIA 模型权重，不把通用光流当作游戏原生运动矢量，也不承诺解决所有模型产生的细节或人物外观变化。

计划起草时本地读取工具启动失败；首轮实施现已核验本仓库已有 `streamline-fg/native-nr` 管线。实际落点、数据契约、验证和剩余限制见 [首轮实施记录](dlss5-generic-nr-pipeline-implementation.md)。下面的概念接口仍不能自动视作仓库已有能力。

### 工程落点

| 层 | 职责 | 实施原则 |
| --- | --- | --- |
| 本仓库 Rust 侧（`src-tauri`） | 能力探测、配置校验、预设、组件版本记录、启停和诊断结果 | 优先沿用已有结构；不让普通配置代码承担每帧 GPU 工作 |
| NR 运行组件 / add-on | GPU 资源接入、NR 实例调度、Look shader、历史和同步 | 先验证已有组件能否直接满足需求，再决定是否维护独立组件 |
| 模拟器渲染后端 | 在需要原生深度或运动资源时提供准确的纹理和时序 | 通用方案首版不要求修改 Eden / Citron 源码 |

本次只新增计划文档。后续本仓库代码默认在 `src-tauri` 实施；需要新增或修改独立运行组件、shader 或模拟器源码时，先明确实际目标仓库与实施范围。

## 2. 已确认的参考能力与待核验条件

公开的 RenoDX NR 源码中已有独立 NR handle 串联、每实例历史重置和外部 Look stage。其四遍上限属于插件实现，不是本计划必须照搬的限制。

公开的 Eden / Citron 渲染代码有定位深度纹理的机制，但“存在深度资源”不等于已经找到与当前显示画面匹配的主场景深度。原生运动矢量还需要识别游戏是否生成、存放位置、编码和对应帧。

DLSS5-Feeder 提供 Vulkan 到 D3D12 的接入路线，读取 ReShade 深度及外部光流 shader 输出。这是首轮实验的候选方案，不能据此认定具体模拟器、游戏、显卡或插件版本已经验证通过。

开始实施前记录：

- 当前工程是否已有可复现的一遍 NR 输出，实际使用哪个运行组件。
- 模拟器、ReShade、feeder、NR add-on、驱动、模型 DLL 的具体版本与文件哈希。
- 显卡、图形 API、NR 输入尺寸、模拟器内部渲染尺寸和最终输出尺寸。
- 深度、运动矢量的来源与质量；区分原生、估算、占位和缺失。
- 当前运行组件能否暴露逐遍参数及 Look 参数，是否需要自行实现 GPU 处理。

## 3. 通用管线

```text
模拟器颜色 / 可用引导资源
          │
          ▼
接入适配器：尺寸、颜色空间、坐标和 GPU 同步
          │
          ▼
NR 调度器：实例 A → 可选实例 B → 后续可选实例
          │                    │
          │                 各自历史
          ▼
Look stage：变化量控制 → 可选空间处理 → 可选时序处理
          │
          ▼
沿用接入层的 SDR / HDR 合成与输出
```

首版 Look 位于最后一遍 NR 之后，保留最后一遍实际输入和输出作为变化量计算依据。该语义已在当前代码中实现；第 10 节计划增加显式的“整条链”作用范围，并保持旧配置的最后一遍语义。暂不增加每一遍都执行 Look 或将稳定结果反馈到后续 NR 的行为。

### 数据契约

帧输入至少包含：

- `source_frame_id`：源渲染帧编号；与呈现编号、插帧编号分开。
- 颜色纹理、格式、尺寸、有效区域和生命周期。
- 颜色空间、传递函数，以及 HDR 时接入层已有的曝光 / 单位契约。
- 可选深度和运动纹理，以及各自尺寸、有效区域和坐标约定。
- 运动方向、单位、缩放、是否含 jitter，以及质量标记。
- 场景切换、分辨率变化和设备重建等重置信号。
- 所属 GPU / device、提交队列及完成同步信息。

深度与运动质量是显式能力，不用一张全零纹理冒充有效数据。若运行时需要占位资源，必须在能力和诊断中标记其实际性质。

同一源帧只推进一次每个实例的历史。若接入层只能看到 Present，必须先核实重复呈现、暂停和插帧的识别方式；不能直接把每次 Present 都当作新的游戏帧。

## 4. 多次 NR 推理

### 首版功能

- 支持一遍和两遍；默认一遍。更高遍数在性能和稳定性验证之后再开放。
- 每遍独立持有 NR handle、参数块和历史重置状态。
- 第一遍读取接入层的颜色；第二遍读取第一遍按既有 codec 正确处理后的输出。
- 引导资源来自同一源帧；不能随意缩放、改变运动单位或混用不同帧的数据。
- 中间纹理采用 ping-pong，保证输出不会覆盖尚在读取的输入。
- 所有纹理处理留在 GPU；首版不设计逐帧 CPU 图像读回。

### 参数与历史

- 每遍可配置强度，以及经实际运行组件确认支持的模型参数。
- 默认第二遍继承第一遍参数；只有关闭继承时才使用第二遍独立设置。
- 场景切换、实际尺寸变化和输入解释变化时协调重置所有相关实例。
- 改变模型实例创建契约时重建实例；普通 Look 滑块不重建 NR 实例。
- 每遍历史是否保留须明确配置和日志；不能默默让第二遍每帧 Reset。
- 减少遍数或关闭 NR 时，等待对应 GPU 提交完成后释放实例和纹理。

### 失败行为

第二遍创建或执行失败时，输出已完成的第一遍，并记录失败原因。失败状态必须有重试策略或显式恢复入口，避免每帧重复创建造成卡顿。

## 5. Look stage

### P2：基础变化量控制

保留模型实际输入 `P` 和输出 `N`，在一致的分辨率及线性颜色空间中计算变化量。参考形式为：

```text
e = log2(max(N, epsilon)) - log2(max(P, epsilon))
```

调整后的变化量用于生成新的模型输出，再进入原有输出合成。实现需明确暗部可信度保护；不能只靠除零下限就放大接近黑色区域的数值误差。

第一批参数：

- 整体增强幅度。
- 提亮、压暗的独立增益和软上限。
- 颜色变化和色相偏移的独立增益。
- 阴影、中间调、高光区域的变化量控制。

中性参数必须保留 NR 原输出。允许完全绕过 Look dispatch，避免多余转换改变 SDR / HDR 结果。NR 关闭时也应绕过整个新增管线。

不能直接把原始 HDR 颜色和经过压缩、归一化的 SDR 模型输出相除。Look 必须遵守当前接入层的输入 / 输出 codec 契约，避免重复 tone mapping 或错误曝光还原。

### P3：空间处理

- 以输入亮度为引导，对亮度变化量做空间分离。
- 独立调整大范围光照变化与细小变化。
- 对满足邻域条件的边缘压暗变化执行光晕抑制。
- 半径按 NR 工作分辨率解释，避免输出分辨率变化后效果尺度失控。
- 验证平坦表面、真实阴影、文字边缘和大反差轮廓，避免新增亮框或破坏原有阴影。

基础空间处理只依赖当前帧颜色及 NR 输入 / 输出，不要求游戏原生运动矢量。

### P5：可选时间平滑

- 保存上一源帧的模型变化量，而不是直接累积整张最终画面。
- 优先使用已经验证的运动资源；通用方案可使用光流估算。
- 重投影后进行邻域限制、置信度判断和历史拒绝。
- 平滑时间以毫秒表达，按实际帧间隔计算混合系数。
- 遮挡、视角切换、暂停恢复、较大时间间隔及尺寸变化时拒绝或重置历史。
- 输入质量不足时减少历史混合；没有可信运动资源时默认关闭运动补偿平滑。
- Look 的历史与 NR 内部历史分别管理，不能为了调整 Look 而每帧重置模型。

该阶段不阻塞基础 Look 或两遍推理。它依赖运动数据质量，必须单独验收，不能靠静态截图判断效果。

## 6. 配置、预设与诊断

### 配置语义

- 配置包含 schema 版本、遍数、逐遍参数、Look 参数和时序策略。
- 默认 NR 沿用既有开关；新增多遍默认为一遍，Look 默认为中性，平滑默认关闭。
- 参数与实际后端能力匹配，不支持的参数明确报告，避免显示已启用却没有效果。
- 预设按模拟器、游戏和必要的显示模式区分，保存运行组件版本以便复现。
- 导入配置时校验有限浮点数、数值范围和枚举；迁移保持已明确选择的参数。
- 恢复默认与绕过新增功能是独立且可验证的操作。

### 诊断信息

- 当前模拟器、接入路径、运行组件及模型文件版本 / 哈希。
- 颜色、深度、运动矢量的来源、尺寸和可信状态。
- 当前执行遍数、每遍是否成功、是否重置历史以及原因。
- 各阶段 GPU 耗时：接入 / 拷贝、逐遍 NR、Look、输出。
- 活跃实例与纹理数量、显存占用，以及等待释放的资源数量。
- 能力不足、失败降级和不支持参数的明确原因。

渲染组件内部调试可提供颜色、深度、运动、变化量和历史权重视图。普通用户配置界面只展示有助于选择和排错的信息。

## 7. 实施顺序与阶段验收

| 阶段 | 工作 | 验收条件 |
| --- | --- | --- |
| P0：工程与接入调研 | 阅读本地说明和代码；确认运行组件；固定测试组合；核实许可证与参考代码版本 | 给出真实工程落点和已支持能力，不把候选方案记为已完成 |
| P1：一遍基线 | 跑通当前接入；确认颜色契约、源帧节奏、同步和重置 | 开关效果可见；旁路输出保持原路径；连续运行和窗口切换稳定 |
| P2：基础 Look | 实现变化量、明暗 / 颜色控制及中性绕过；接入 Rust 配置和诊断 | 中性保持 NR 输出；暗部无 NaN / 闪点；明暗和颜色限制有可复现效果 |
| P3：空间 Look | 大范围 / 细节分离及光晕抑制 | 对照视频中边缘问题改善；平坦区域、文字和真实阴影不出现明显新增伪影 |
| P4：两遍推理 | 独立实例、历史、ping-pong、参数继承和失败降级 | 第二遍生效；每个源帧只推进一次各实例历史；降级稳定且资源可回收 |
| P5：时序 Look | 光流或已有运动资源接入、重投影、置信度和历史拒绝 | 慢速平移闪烁减少；快速转向、遮挡和切场景没有不可接受的拖影 |
| P6：预设与集成 | 保存 / 导入 / 迁移预设，能力提示，完整回归 | Eden / Citron 分别有实际测试记录；预设可复现；不支持组合有明确状态 |

首个可交付版本为 P0–P2。空间处理、多次推理和时间平滑分别推进，避免把所有功能绑成一次大改动。

## 8. 验证方案

### 正确性

- 使用固定输入检查中性 Look、完全绕过、零变化量和极暗 / 极亮区域。
- 检查 SDR 与实际支持的 HDR 契约，确认无重复转换、黑位漂移和非有限值。
- 用真实运动序列检查方向、单位、有效区域、动态分辨率及历史重置。
- 在原画、一遍 NR、一遍加 Look、两遍 NR、两遍加 Look之间做独立对照。
- 保留输入帧、参数、版本信息和输出；不能仅凭不同场景的截图判定算法收益。

### 游戏场景

至少选用一个 Eden 和一个 Citron 的实际测试组合，覆盖写实风格与卡通 / 风格化画面。场景包含：

- 暗处进入亮处、光照闪烁和高反差轮廓。
- 慢速平移、快速转向、遮挡与显露。
- HUD、字幕、透明物体、粒子和细小植被。
- 暂停、读档、切场景、窗口 / 全屏切换及分辨率改变。

原生深度、估算运动和占位资源等组合分开记录；不把原生 DLSS PC 游戏的经验直接写成模拟器验证结果。

### 性能与资源

- 固定硬件、驱动、版本、分辨率、输入质量和场景。
- 分别记录源帧帧时间、各阶段 GPU 耗时、显存、CPU 开销和长帧。
- 分开统计预热 / 创建开销与稳定运行开销，不用插帧后的 FPS 代替 NR 耗时。
- 循环切换遍数、开关和分辨率，验证实例与纹理数量最终回落，不持续增长。
- 依据实测决定是否开放更多遍数、低分辨率 Look 或更强的平滑，而不预先承诺性能提升。

后续若修改 Rust，按仓库要求执行 `cargo fmt`、host 与 Windows target 的 `cargo check`，并解决出现的错误和警告。GPU 运行组件使用其自己的构建、shader 编译和实机验证流程。

## 10. Magpie 0.6.9 参考与后续实施计划

补充日期：2026-10-05。当前实现基线为本仓库提交 `b6c71e1`；参考对象为 **SAOG0721/Magpie 独立实验分支**的 `v0.6.9-experimental`（发布提交 `27c5df9`），不是 Blinue/Magpie 上游。以下均为待实施或待对照的工作，不改变当前运行能力声明，也不将 Magpie 的合成测试当作本项目的游戏验收。

### 10.1 当前差异与取舍

| 项目 | 本仓库当前行为 | Magpie 0.6.9 参考 | 后续取舍 |
| --- | --- | --- | --- |
| Look 作用范围 | 一遍用 `(P0, R1)`，两遍用 `(R1, R2)`；两遍的 Look 强度为 0 仍保留第一遍效果 | 以最初输入与最终输出提取整条链的总修正 | 增加显式作用范围；旧配置保持最后一遍语义 |
| 时间平滑 | NVOF 重投影、输入颜色验证、邻域限制；当前零修正不引入旧增强 | 静态、光流、持续性与低频重建四种开启路线；当前版本稳定整链总修正 | 复用已有基础，分别增加静态备选与持续性增强，不一次更换所有算法 |
| 历史验证基准 | 与 Look 配对的模型输入；两遍时为可能自身波动的 `R1` | 用未经 NR 修改的原始颜色判断历史对应关系 | 将颜色引导与待累积变化量分离 |
| 历史插值 | 四点双线性混合后验证颜色 | 低频重建路线逐个验证历史采样点，再归一化有效支持 | 单独试验逐点验证，测量边缘收益和带宽开销 |
| 参数与缓存 | 重复输入复用最终结果，普通调参等待新颜色；下一张新颜色仍走 NR | NR 与出口控制分别缓存；纯出口调参不增加 NR，某层调参只重算该层和后续层 | 拆分修订与缓存，支持暂停画面即时 Look 调参 |
| 多遍调度 | 第二遍前提交并等待第一遍，支持安全降级 | 共用队列、围栏和命令环，同一命令列表顺序录制；多层失败拒绝整链 | 在同步基线稳定后减少等待，并明确保留或调整失败恢复契约 |
| 颜色与细节 | log 变化量、明暗/颜色/色相/区域调节、空间高低频与光晕抑制 | Oklab 明度/色度、保护、过度修正抑制和诊断视图 | 作为独立颜色算法实验与界面简化参考，不能只按名称映射数值 |
| 降低推理尺寸 | 当前 NR 与 Look 使用已有同尺寸 SDR 契约 | SDR 入口只降采样一次，所有层在同一推理尺寸串联，出口重建总修正 | 后期单独加入，先明确尺寸、运动单位、重建和模型支持边界 |

当前本项目的时间阶段在空间 band 与最终 Look 调节之前处理原始模型 log 变化量；Magpie 抗闪烁位于出口修正和重建之后，处理有符号 RGB 差分。两者的数值空间和顺序不同，不能直接搬用阈值、时间历史或 shader。Magpie 从 0.6.8 的后续层增量稳定改为 0.6.9 的总修正稳定，也必须按固定版本解释。

### 10.2 Look 作用范围与原图引导

设 `P0` 为完成当前 crop/flip/codec 解释后的原始 NR 输入，`R1`、`R2` 为两遍未经外部 Look 修改的输出。

- 拟增加 `look.scope = final_pass / chain_total`。字段缺省、旧协议和旧预设均迁移为 `final_pass`；首轮保持新配置默认一致，整链模式由用户显式选择。
- `final_pass` 保留当前配对：两遍 `(R1,R2)`，一遍或安全降级 `(P0,R1)`；`chain_total` 使用 `(P0,最后成功输出)`。
- 中性 Look 和完全旁路保持最后成功 NR 输出；强度为 0 返回所选范围的基底 RGB，alpha 沿用当前最终模型 alpha 契约。界面明确：最后一遍范围的 0 保留第一遍，整链范围的 0 返回原图 RGB。
- 时间历史验证单独读取原始 `P0` 及其历史；累积对象仍按所选范围计算。原图、变化量和运动必须处于同一尺寸、有效域与坐标基准，不能用未映射的 Present 图像代替 `P0`。
- scope 改变、实际成功遍数改变、降级/恢复、尺寸或输入映射变化均使相关 Look 历史失效。旧缓存不得跨范围复用；单纯 scope/Look 修改不重置 NGX 模型历史，但更新输出时沿用下游 SR/FG 历史边界。
- 若原图本身噪声导致频繁误拒绝，再独立比较轻度保边的原图引导；不先默认增加预滤波，也不使用 NR 残差作为判断真实场景变化的唯一依据。

验收：一遍、两遍和第二遍降级分别覆盖两个 scope；中性逐位一致、0 强度基底、alpha、原图验证基准、切换重置及预设迁移均有固定输入证据。用相同视频分别观察第一遍闪烁和第二遍新增闪烁，决定是否推荐整链范围。

### 10.3 抗闪烁模式与历史采样增强

拟增加明确模式：关闭、静态累积、光流累积、光流累积＋；低频时域重建保留为后期独立实验。旧 `temporal.enabled=false` 对应关闭，旧开启配置对应现有光流累积，保留 timeMs/strength/rejection 的显式值。新枚举、scope、状态和预设需版本化，并增加组件能力检查；旧组件遇到不支持的非默认设置明确拒绝。

**静态累积：** 不使用运动补偿，在同一位置验证原图局部颜色与边缘稳定性，仅混合可信区域的变化量。用于固定镜头对照及无光流时的显式备选；不把全零运动冒充有效光流，也不宣称静态模式解决运动闪烁。光流失效时默认按现有行为旁路；若提供静态回退，必须显式配置、清理旧运动历史并报告实际模式，避免暗中切换。

**光流累积：** 保留现有 NVOF 路径，将原图引导与变化量分离。对重投影的四个历史采样点逐个检查有效域、有限值、历史有效标记和颜色相容性，再按双线性权重与接受度归一化。有效支持不足时使用当前值，不能放大单个微小权重。它仍是颜色启发式；本项目没有已验证的真实遮挡、法线或逐像素光流 cost，不能声称具备几何遮挡判定能力。

**光流累积＋：** 分别维护修正的存在支持与存在时的条件幅度；缺失观察更新支持，但不把零混入条件幅度。出现较快、消退较慢，真实输入变化或历史失效立即拒绝旧修正。Magpie 的 60 ms 出现、180 ms 消退、80 ms 幅度仅作参数扫描起点；阈值需在我们的线性/log 契约内重新标定。特别对照当前“零修正立即退出”的策略，验证出现/消失、正负翻转、长期缺失与真实短暂光照，避免旧修正粘住。该路线可能改变时间均值，不自动替代普通光流模式。

**低频时域重建：** 若视频证明宽范围明暗呼吸仍明显，再试验低分辨率低频观察、原尺寸历史和颜色引导重建，当前高频保留。它与降低 NR 推理尺寸是两项独立功能；不以新增低频历史宣称减少模型推理成本，也不保证消除高频闪烁。

共同要求：只在新颜色观察上推进时间历史；同一源帧上的参数重算只重新合成，不计为新增时间样本。沿用场景/输入边界、暂停恢复、超过 250 ms 间隔及资源重建的重置；新增模式切换清历史。记录实际模式、引导基准、有效采样支持、历史接受比例、纹理分配和 GPU 耗时；全局权重上限不能当作实际接受比例。

验收：合成序列逐项覆盖稳定幅度抖动、有/无交替、反向修正、单帧脉冲、长期消失、真实输入变化、亚像素前景/背景边缘、同色物体、越界和无效历史；同时覆盖完全重复输入不推进历史。Eden/Citron 视频比较关闭/静态/现有光流/逐点验证/持续性增强，记录闪烁、拖影、响应延迟及耗时，不以合成测试替代真实视频。

### 10.4 模型、Look 和输出缓存拆分

- 分开维护源输入、引导/映射、各遍模型参数、Look 参数及输出修订；明确每项改变使哪些缓存和历史失效。颜色相同但引导/reset 边界变化不能错误命中模型缓存。
- 保留未经 Look 覆盖的各遍输出。当前最终合成会写回 NR 输出，实施前必须安排独立合成目标或等价的原始结果缓存，否则反复调参会对已调整结果重复施加增益。
- 完全重复且契约未变时复用输出。纯 Look 更新复用原始模型结果，只重做必要的空间/合成与交接；暂停画面也能即时看到调参，不增加任何 NR Evaluate，不推进时间历史。
- 第二遍模型参数变化只失效第二遍及下游；第一遍参数变化失效两遍。缓存重算与新的源颜色观察分开计数，明确 NGX reset 与帧调用合同，不能假装参数重算是新游戏帧。
- 隐藏/关闭层的参数保存不扰动活动链；恢复该层、重试、失败降级和资源退休沿用明确生命周期。新状态区分实际 NR 推理、Look 重算、输出复用与待应用参数。

验收：固定源图反复调整 Look，Evaluate 计数不增、结果不累计漂移且能回到中性；单改第二遍时第一遍计数不增；输入/引导/参数边界均按实际依赖失效。测试跨 NR→SR→FG 的输出更新与历史重置、失败恢复、退休和长期纹理数量，记录新增缓存的真实显存成本。

### 10.5 颜色保护、诊断和界面

- 保留现有 log 变化量算法，独立试验 Oklab 明度/色度分离；中性、超范围候选、暗部、色相、最终色域限制和非有限值均有数值对照。切换算法需显式保存和迁移，不能将原参数数值默默解释为另一颜色空间。
- 基础面板优先呈现总强度、颜色变化、明暗变化与作用范围；进阶提供色相/暗部/高光保护、过度修正抑制、低频/高频、光晕和时间控制。折叠只改变展示，不改变参数或处理。
- “阴影/结构”“高光/辉光”等名称必须说明对应的实际明度方向或区域规则；不暗示识别了真实阴影、结构、反射或辉光。已有空间 lighting/detail 的含义也不直接映射成 Magpie 同名强度。
- 增加原图、各遍输出、原始/受控变化量、低频/高频、保护权重、历史有效性与接受权重视图。诊断期间不反馈到 NR；进入/退出清理受显示切换影响的外部历史，测性能时关闭读回与诊断开销。
- 本阶段沿用当前 SDR sRGB nonlinear 模型、线性处理契约。Magpie 的 HDR、Oklab 阈值及 RGB 残差不能直接迁移；HDR 需独立 codec/曝光设计与验收。

### 10.6 多遍调度与降低推理尺寸

先用已有计时量化输入比较等待、第二遍前的 CPU fence 等待、各遍 GPU Evaluate、Look 与输出交接。2026-10-06 按用户澄清，停止重复核验已在增强关闭时出现的模拟器原有错误，不把它们作为 M5/M6 实施前置条件；保留未过滤日志，针对新增管线继续执行核心/同步检查和故障恢复验证。整链严格验收状态仍单独记录。

在安全基线上评估共用命令环、同队列连续录制和 GPU barrier，减少第二遍前的 CPU 等待；保留独立 Feature、参数、历史和可供缓存重算的各层结果。不能只用两张 ping-pong 纹理覆盖所有前缀缓存。

当前安全降级依赖已完成的第一遍。减少等待前须证明失败第二遍的录制可丢弃、第一遍可独立完成和交接；无法保持时明确采用整链拒绝并重新设计恢复策略，不静默改变行为。提交/等待失败不能当作可继续使用的完整结果。按 CPU 等待、GPU 阶段、提交数、带宽、显存及长帧评估收益，结构计数减少不等于实测性能提高。

后续降低推理尺寸时，在入口保留原图并只降采样一次；各遍在相同推理尺寸串联，出口重建受控总修正并加回原尺寸基底。同步缩放运动/深度和有效域，明确变化量的数值空间、单位与半径，保留当前 alpha 合同；它不是原流程的天然等价优化。验证输入比例、重建过冲、细线/HUD、暗部、模型最小支持尺寸、动态尺寸重建及两遍/Look/SR/FG 组合。模型边界须实测，不能用 shader 的 1×1 成功证明 NR 模型支持 1×1；首轮默认关闭，不提前照搬 Magpie 的 25% 下限或扩展到 HDR。

### 10.7 实施顺序与完成门槛

2026-10-06 追加用户要求：尺寸控制先移到 NR 高级配置第一项并加入固定长边上限，随后进一步拆出为主面板效果上方的独立“输入尺寸缩放”。公共入口向 NR／SR 提供同一小尺寸源图；NR 关闭或未安装模型也可使用，NR／SR 都关闭时恢复到窗口尺寸交给 FG，FG 最终呈现尺寸保持不变。上限以像素表示，超过时等比缩小、不放大小输入，并取代比例；缺省仍为 100% 且无上限。旧数值迁移到公共字段，但公共整图缩放与旧 NR 专用变化量重建的画质语义不同。实现记录见 [公共输入缩放](dlss5-generic-nr-pipeline-implementation.md#独立公共输入尺寸缩放2026-10-06)。按用户最新分工，功能／GPU 测试由用户进行，代码编译与打包不代表以下验收门槛全部通过。

以下为原始实施门槛；顺序在测量发现新问题后可调整，每项独立对照与回退。2026-10-05 已接续实现 M1、M2 三种时间模式/逐点验证、M3 模型后缀与 Look 重合成、M4 颜色保护/Oklab/诊断；见 [本轮实现记录](dlss5-generic-nr-pipeline-implementation.md#模型后缀重算光流累积与颜色诊断2026-10-05)。不将这些代码、数值检查和隔离 GPU 结果记为整项视频/实机会话验收通过。

| 顺序 | 任务 | 完成门槛 |
| --- | --- | --- |
| M0 | 固定当前组件/模型/源代码与测试视频，定位并修复既有同步/布局问题 | 保存未过滤的原始验证日志，按实际归属修复；严格门槛通过前不报告整链验收完成 |
| M1 | 显式 Look scope 与原图历史验证基准 | 两范围、一/两遍、降级、0/中性/旁路、历史边界、旧配置迁移均验证 |
| M2 | 静态模式、逐采样点验证、光流累积＋，逐项落地 | 固定序列数值正确；真实运动视频证明收益，记录拖影/延迟/成本；保留旧模式 |
| M3 | 模型/Look/输出缓存与修订拆分 | 静止调参即时生效且无 NR 重算/时间推进；后缀重算、交接及退休证据通过 |
| M4 | 保护/过度修正抑制/诊断视图与界面分组；Oklab 独立实验 | 参数含义、迁移、中性、极值、真实画面与诊断旁路验证 |
| M5 | 集中多遍 GPU 调度 | 严格同步/核心验证、故障注入/失败恢复、正常退休和性能对照通过 |
| M6 | 降低 NR 推理尺寸与可选低频时域重建，分别实施 | 颜色/坐标/重建契约、模型尺寸边界、视频画质、组合稳定性与耗时/显存均有记录 |

每项修改 Rust 后执行 `cargo fmt`、工具箱/涉及运行组件的 host 与 Windows target `cargo check` 并解决错误和警告；shader 更新需重新编译、`spirv-val` 和构建摘要检查，GPU 算法改动执行相应硬件测试。真实视频画质与性能分别验收；标题场景 FPS、固定输入或 NGX 合成测试均不能单独完成这些门槛。

2026-10-06 实时输入缩放接续：v11 为公共输入设置增加独立会话修订与下一帧重建，尺寸／模式／恢复原尺寸均可实时调整，NR 关闭也允许使用。旧 v10 会话仅在升级组件后需重新启动一次。界面以实际尺寸和渲染应用修订确认生效，暂停时等待恢复；格式、编译和交付校验与功能／GPU 验收分开，后者按用户要求由用户自行执行。详见实现记录的“输入尺寸实时调整”。
