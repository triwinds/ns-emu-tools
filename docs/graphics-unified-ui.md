# 统一图形增强界面（2026-10-18）

## 设计方向

页面的主要任务是给模拟器组合画面效果。以处理顺序而非厂商组织界面，
共用目标、组件检查、输入尺寸和启动入口。保留应用现有深浅主题。

浅色参考：雾白 `#F5F7FA`、石墨 `#253247`、灰蓝 `#68788D`、
操作蓝 `#356AC3`、运行青 `#287D76`、限制琥珀 `#9A651D`。
正文沿用 Segoe UI／Microsoft YaHei UI，标题 23px、效果标题 18px、
正文 14px、辅助文字 13px。全部左对齐，说明文字限制在约 76ch 内。

比较了保留两张厂商设置卡与按处理阶段排列两种布局。前者继续重复安装和
启动入口，无法清楚表达混合组合，因此选用后者；只有 SR／FG 共用工作区
使用明显边框，组件清单保持轻量行结构。截图复查后进一步去掉目标程序的
重复路径、缩短顶部目标区，使效果选择更靠前。没有添加装饰动画。

## 行为与能力边界

- SR／AA 与 FG 的开关、引擎分别选择；不再提供厂商页签。
- DLSS SR／DLAA + DLSS FG、DLSS SR／DLAA + XeSS FG、
  XeSS Native AA + XeSS FG 使用现有执行路径。
- XeSS Native AA 与 DLSS FG 或 NR 的组合显示明确限制，阻止启动。
  XeSS Native AA 仍是同尺寸抗锯齿，没有新增 XeSS 超分辨率。
- RTX 40／50 且两套组件已安装时，纯 FG 也优先使用可切换的 NVIDIA 会话。
  其他纯 XeSS 效果沿用独立启动路径。NVIDIA 启动会校验并预备可用的 XeSS 运行库；
  选择 XeSS 时它是必需组件，选择 DLSS 时缺失 XeSS 只会关闭热切换能力。
- 输入尺寸使用同一份页面设置，并同步给两个后端。可用的运行会话收到实时请求，
  实际应用尺寸仍以运行记录为准。
- 选择保存于版本化的 `ns-emu-tools:graphics-effects:v1`，首次读取既有设置。
  启动前再次同步后端参数；任一配置写入失败都不继续启动。
- 具有 `fgBackendSwitchSupported` 的新会话支持 DLSS FG / XeSS FG 热切换；
  旧会话或独立 XeSS / Native AA 会话保持原有重启提示。
- 高级对话框、NR 设置、组件校验和运行记录继续使用既有控制器。
  统一界面的 FG“恢复默认配置”保留选中的引擎。

## 验证

`frontend/tests/graphicsPipeline.test.ts` 覆盖组合分流、逆向混合限制、
NR 依赖、暂停时的桥接依赖与损坏的持久化设置。

浏览器使用模拟 IPC 验收保存与命令分流，没有通过测试界面修改用户配置。
验证了混合启动、纯 XeSS 启动、无 NVIDIA 显卡、未支持组合、组件缺失、
检查失败后可重新检查、DLSS 高级配置入口，以及深浅主题。
窄窗口检查的实际内容宽度约 398px，未出现横向溢出。
测试预览及调用记录保存在本地 `build/graphics-ui-20261018`，不参与交付构建。

## 引擎高级页与切换修正

XeSS FG 的高级页只列出实际固定配置：2×、零运动向量、深度 0.5 和 XeLL。
NVIDIA 光流质量与时间提示移到独立的 DLSS 重建／NR 光流入口；该入口隐藏
DLSS FG 专用的静态区域、边界保护及阈值。DLSS FG 的高级页继续保留这些参数。
没有编造可调整的 XeSS 内部光流设置。

新 NVIDIA 会话在两套组件通过校验后使用 `--fg-switchable`，启动时保留 Streamline
交换链，并在独立的窗口消息线程准备 XeSS 显示层。游戏交换链、SR 和 NR 保持可用。
每次切换先退役上一帧的处理和 FG 消费，暂停旧 FG / 延迟控制，重置历史后选择新引擎。
XeSS 显示层必须持续处理窗口消息；窗口线程退出并 join 后才允许卸载 DLL。

界面根据当前会话能力发送包含引擎、FG 开关、修订号的原子控制。显示“当前引擎”
始终读取实际遥测，切换中等待 backend 和 appliedRevision 确认；失败或超过 8 秒
未确认时提供重试。DLSS 倍数使用单独保留的 `dlssMaximumGenerated`，避免误用
XeSS 的固定 2× 上限。旧会话继续使用暂停并重启的流程。

验证详见 [FG 热切换验证](fg-hot-switch-validation.md)。
